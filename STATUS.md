# Статус проекта НайдИИ

Короткая справка для быстрого старта в новой сессии (например, на другом компьютере) — что уже сделано,
где что лежит, что дальше. Полное ТЗ обсуждалось в чате и не хранится файлом в репозитории, за
исключением одной правки — см. раздел «Ожидает решения» ниже, она записана в отдельный файл.

## Готово — раздел «Новости и статьи» (2026-10-08)

Отдельный раздел `/news` (в шапке — «Новости»), публикует только админ из `/admin` → вкладка «Новости».
- **Данные:** миграция [`1755000063_news.js`](pocketbase/pb_migrations/1755000063_news.js) — `news_posts` (заголовок, slug,
  рубрика `news`/`article`, анонс, текст, миниатюра-файл, статус черновик/опубликовано, `published_at`) и `news_images`
  (картинки внутрь текста). Анонимам видны только опубликованные с `published_at <= сейчас` (можно запланировать выход
  на будущее — страница подхватит сама, ISR 60 с); создание/правка/удаление — только `role = admin`. Проверено на копии
  боевой БД: аноним видит 5 из 6 (будущая скрыта).
- **Текст — Markdown** (`react-markdown` + `remark-gfm`, новые зависимости): `##`/`###`/`####` — заголовки трёх
  степеней, `**жирный**`, `*курсив*`, цитаты, списки, ссылки, таблицы, фото с подписью `![подпись](url)`. Сырой HTML
  не пропускается — XSS через текст невозможен. Рендер — `components/news/NewsBody.tsx`.
- **Редактор** (`components/admin/NewsTab.tsx`): кнопки Заголовок/Подзаголовок/Мелкий/Ж/К/Цитата/Списки/Ссылка/
  Разделитель, «Фото в текст» (загрузка в `news_images`, спрашивает подпись), загрузка миниатюры, живой предпросмотр
  рядом, рубрика, дата, «Опубликовать» / «Сохранить как черновик», удаление. Slug из заголовка (транслитерация).
- **Публично:** `/news` — фильтр Все/Новости/Статьи, крупная первая карточка + сетка «квадратиков» (обложка, рубрика,
  дата, заголовок, анонс; без обложки — градиент по рубрике); `/news/[slug]` — кнопка «← Все новости и статьи»
  сверху и «Вернуться к списку» снизу, обложка, текст, «Читайте также», JSON-LD `NewsArticle`/`Article`, OpenGraph;
  главная — колонка «Новости и статьи» (5 свежих) под блоком AI-событий (`components/news/NewsSidebar.tsx`);
  sitemap дополнен.
- Админский скрипт создания через интерфейс проверен в браузере на копии БД (статья с обложкой и фото в тексте);
  мобильная ширина — без горизонтального скролла. На проде публикаций пока нет — первую создаёт админ.

## Готово — счётчик Яндекс Метрики (2026-10-02)

Счётчик `113331917` (код выдан пользователем, с вебвизором, картой кликов, ecommerce и trackLinks) встроен во все
страницы через корневой `app/layout.tsx`: обычный inline-скрипт в `<head>` (не `next/script` — тот при

`ym(id, 'hit', url, {referer})` вручную (первый рендер пропускает — его уже посчитал init). Отключён в сборке для
GitHub Pages (`STATIC_EXPORT=true`): там другой хост, его просмотры не должны попадать в счётчик naidii.ru.
Вебвизор записывает действия посетителей, включая заполнение форм (пароли Метрика маскирует сама) — при
необходимости добавить в политику конфиденциальности. Проверено: typecheck, сборка, скрипт и noscript в HTML,
`window.ym` и `Ya.Metrika2` на странице, ошибок в консоли нет.

контент там и так лежал в одной обёртке); для `SpecialistCard.tsx` обёртку добавили отдельно. Проверено:
typecheck, `npm run build`, визуально в браузере (свечение появляется в углу при наведении, текст не
перекрыт, карточка поднимается).

## Готово — закрытая база потенциальных исполнителей в админке (2026-09-27)

Вкладка «База исполнителей» в `/admin` (только роль admin, модераторам не видна): картотека контор, которых
приглашаем на площадку. Ни с чем на сайте не связана. Коллекция `prospects` (миграция `1755000054`, все

почты, Telegram, услуги, цены, кейс, достоверность, автоматические пометки о происхождении данных
(`data_notes`), **статус** (не связывались / написали / ответили / работаем / не работаем), **примечание**
админа, дата последнего контакта, дата сверки. Поиск, фильтры по статусу и направлению, «без контактов»,
добавление вручную, удаление, **импорт и экспорт CSV** (одинаковый формат; `;` + BOM, открывается в Excel).
Повторный импорт не плодит дубли (контора ищется по домену) и не трогает статус, примечание и дату контакта;
пустые значения из файла ничего не стирают.

**Сами данные в репозиторий не кладутся** (это контакты и реквизиты сторонних компаний и ИП, репозиторий
публичный): файл собран отдельно и загружается админом кнопкой «Импорт CSV». Первая загрузка — 51 контора:
30 по направлению AI-агенты и 21 по RAG (Perplexity), контакты и реквизиты пополнены с их же сайтов (главная,
контакты, реквизиты, политика конфиденциальности) и из открытого реестра ФНС `egrul.nalog.ru` по ИНН. ИНН
проверяется контрольной цифрой; ИНН физлица (в реестрах ЮЛ и ИП его нет) в базу не записывается. Зарубежные
компании (4 из 51) получили предзаполненное примечание. Скрипты сбора — разовые, в репозиторий не входят;
кнопка «обновить с сайта» и периодический парсинг — возможное продолжение (`checked_at` уже есть).

Проверено на реальном PocketBase: закрытость от аноним/специалист/модератор, импорт настоящего файла,
повторный импорт без потери ручной работы, экспорт→импорт без изменений, дубли, в браузере под админом
(статус, примечание, поиск, фильтры, импорт через интерфейс).

**Направления (2026-09-27, миграция `1755000055`).** Контора может работать в нескольких из девяти групп
площадки (+ «Другое»): поле `directions` (мульти-выбор, слаги из `data/categories.ts`); старое `direction` —
только «в каком списке нашли». В таблице — подписи-чипы, фильтр по любой группе, правка галочками в
раскрытой строке. Правка галочками ставит `directions_manual`; пока флага нет, повторный импорт CSV может
обновить направления (они автоматические), после ручной правки — не трогает. Миграция заполняет `directions` из
`direction`. Автоопределение (только в файле импорта, не в коде сайта) — по словам на сайте конторы: группа
присваивается при достаточном числе упоминаний, остаются группы не слабее пятой части от главной, не больше
четырёх; оценка грубая, каждая строка сопровождается пометкой, по каким словам это решено.

**10-я группа «Обучение AI и автоматизации» (2026-09-27, миграция `1755000056`).** Слаг `education` есть только в базе контрагентов (не категория каталога): это школы и корпоративные провайдеры как рекламодатели и источник выпускников. Школы в CSV стоят только в этой группе, темы программ лежат в заметках. Концепция раздела, тарифы школ и промокоды выпускников пока не реализованы: ждём отклика первых школ.

- `/admin` — админ-панель: модерация профилей/отзывов, категории, тарифы, неизменяемый журнал действий.

Ни одна из кабинетных/админских страниц не защищена реальной авторизацией — это подчёркнуто баннером на
каждой. Кнопки типа «Написать», «Войти» — без обработчиков.

## Что не готово

- Домен `naidii.ru` теперь резолвится на VPS (`83.147.246.248`) — DNS переключён с бонусного shared-
  хостинга Timeweb (тот отдельный продукт, `hosting.timeweb.ru`, остался неиспользуемым, но уже оплачен
  до марта 2027 — можно пригодиться потом для чего-то ещё). `www.naidii.ru` тоже настроен.
- Автоматического резервного копирования БД (и теперь ещё и фронтенда) пока нет — как и у других
  проектов на этом сервере.
- Переключение фронтенда с моков на реальные запросы к PocketBase — теперь технически возможно (оба
  живут на одном сервере, домен есть), но ещё не сделано — фронтенд всё ещё читает `mock-*.ts`.
- Реальная оплата: схема (`orders`, `site_settings.payment_mode`) уже поддерживает ручной сценарий
  («перевёл → загрузил чек → админ подтвердил») без интеграции с платёжным шлюзом — можно стартовать на
  нём, не дожидаясь выбора и подключения конкретного эквайринга (`payment_provider` пока не выбран из
  перечисленных в схеме вариантов).
- **Пивот на карточки услуг** — первый срез сделан (см. раздел выше, включая форму создания карточки и
  все 42 обложки), но PocketBase-схема ещё не разъединена под модель ResultType/ServiceOffer (миграция
  1755000016 описывает старую 1:1 структуру), и часть разделов правки ТЗ (авто-проверка публикации,
  полная формула ранжирования) не реализована.

## Как продолжить с другого компьютера

```bash
git clone https://github.com/Butman76/naidii.git
cd naidii/web && npm install
```

Дальше можно `npm run dev` для локальной разработки. Доступ на сам сервер (SSH) не привязан к
компьютеру — нужны только реквизиты входа на `spb-3-vm-2v0g`, которые есть у пользователя.

Claude Code в этой папке при старте сессии сам подхватывает [`CLAUDE.md`](CLAUDE.md) в корне репозитория,
который указывает читать этот файл и `PIVOT_SERVICE_CARDS.md` — отдельно просить об этом не нужно.

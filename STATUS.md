# Статус проекта НайдИИ

Короткая справка для быстрого старта в новой сессии (например, на другом компьютере) — что уже сделано,
где что лежит, что дальше. Полное ТЗ обсуждалось в чате и не хранится файлом в репозитории, за
исключением одной правки — см. раздел «Ожидает решения» ниже, она записана в отдельный файл.

## Ожидает решения — прочитать первым

**[`PIVOT_SERVICE_CARDS.md`](PIVOT_SERVICE_CARDS.md)** — 2026-08-22 пользователь прислал правку ТЗ:
главным объектом каталога должна стать карточка услуги (со стандартной автообложкой), а не профиль
специалиста. Это меняет структуру каталога, продвижения и модели данных. **Ничего из этого ещё не
реализовано** — файл содержит полный текст правки, разбор аналога (Playerok.com) и открытый вопрос к
пользователю (направления в примере ТЗ — общая биржа услуг, а не только AI; нужно уточнить, расширяется
ли ниша или пример просто иллюстрирует структуру). Начинать следующую сессию с этого вопроса, прежде чем
переписывать код.

## Что уже готово (на 2026-08-22)

**Backend (PocketBase)**
- Схема данных полностью описана миграциями в [`pocketbase/pb_migrations/`](pocketbase/pb_migrations/)
  — 14 коллекций, соответствуют ТЗ §11 (+ `categories`, добавлена сверх ТЗ для SEO-страниц из §13.1).
  Детали решений и известные грабли PocketBase 0.28 (fields нужно добавлять через
  `collection.fields.add()`, а не списком в конструкторе) — в [`pocketbase/README.md`](pocketbase/README.md).
- Развёрнут и работает на реальном сервере: Timeweb VPS `spb-3-vm-2v0g`, путь `/opt/naidii/pocketbase`,
  systemd-служба `pb-naidii.service`, порт `127.0.0.1:8093` (сервер общий с другими проектами — ПОТОК/
  DudergoFF, боты — там нет Docker, только Caddy + systemd, поэтому и здесь так же).
- Суперпользователь PocketBase создан (`admin@naidii.ru`, пароль знает только пользователь — не хранится
  в репозитории).
- Доступ сервера к GitHub — через отдельный deploy-ключ `~/.ssh/naidii_deploy` на самом сервере (не
  привязан к конкретному компьютеру-клиенту, работает откуда угодно по SSH на сервер).
- **Важный пробел, всплывший при ревью:** в `specialist_profiles` нет поля категории/направления —
  только `skills.category` (свободный текст, не связь). Понадобится новая миграция, когда будем
  привязывать специалистов к направлениям каталога по-настоящему (см. также `PIVOT_SERVICE_CARDS.md`).

**Frontend (Next.js)** — весь на моках, PocketBase ещё не доступен по интернету (см. «Что не готово»).
Автопубликуется на GitHub Pages при каждом push в `main` через
[`.github/workflows/deploy-web.yml`](.github/workflows/deploy-web.yml): **https://butman76.github.io/naidii/**
— временная витрина, репозиторий из-за этого публичный (осознанный компромисс).

- `/` — главная: шапка, hero с поиском, сетка «Топ-20» (5×4 на десктопе, ТЗ §4.4).
- `/specialists` — каталог с поиском, фильтром по направлениям/навыкам, сортировкой.
- `/specialist/{slug}` — профиль специалиста; один из 48 моков (`specialist-5`, «Студия «Автоматика»»)
  показывает **премиум-версию профиля** (обложка, галерея, команда, сертификаты) — визуальный мокап
  максимального тарифа, флаг `premium` проставлен вручную в моках, к реальной оплате не привязан.
- `/categories`, `/category/{slug}` — 10 направлений (`web/src/data/categories.ts`), SEO-поля
  (title/description/H1/FAQ) на каждую, ТЗ §13.1.
- `/tariffs` — витрина 3 тарифов (Старт/Стандарт/Максимальный) по схеме `plans`, без оформления заказа.
- `/dashboard` — кабинет специалиста (Обзор/Профиль/Услуги/Заявки/Отзывы/Тариф), фейковый залогиненный
  пользователь, баннер «демо-режим».
- `/dashboard/customer` — кабинет заказчика (заявки/отзывы/избранное — избранное только визуально,
  в схеме БД ещё не реализовано).
- `/admin` — админ-панель: модерация профилей/отзывов, категории, тарифы, неизменяемый журнал действий.

Ни одна из кабинетных/админских страниц не защищена реальной авторизацией — это подчёркнуто баннером на
каждой. Кнопки типа «Написать», «Войти» — без обработчиков.

## Что не готово

- Домен `naidii.ru` оплачен и отправлен на регистрацию 2026-08-21 (пятница), ожидается ~2026-08-24
  (понедельник). До этого момента у PocketBase нет публичного домена — фронтенд не может получать
  реальные данные, только моки.
- Caddy на сервере ещё не настроен под `naidii.ru` / `pb.naidii.ru` — как только домен заработает, нужно
  добавить блоки в `/etc/caddy/Caddyfile` (закрыть `/_/` от публичного доступа, в отличие от других сайтов
  на этом сервере, где админка PocketBase открыта всем — это оставлять не надо).
- Автоматического резервного копирования БД пока нет (как и у других проектов на этом сервере).
- GitHub Pages — это временная витрина. Для реального запуска нужен Node-процесс на сервере (SSR,
  API-роуты для платежей и админки), т.к. статический экспорт этого не поддерживает.
- Реальная оплата: схема (`orders`, `site_settings.payment_mode`) уже поддерживает ручной сценарий
  («перевёл → загрузил чек → админ подтвердил») без интеграции с платёжным шлюзом — можно стартовать на
  нём, не дожидаясь выбора и подключения конкретного эквайринга (`payment_provider` пока не выбран из
  перечисленных в схеме вариантов).
- Переключение фронтенда с моков на реальные запросы к PocketBase — ждёт домена.
- **Пивот на карточки услуг** — см. «Ожидает решения» выше, самый крупный незакрытый вопрос по ТЗ.

## Как продолжить с другого компьютера

```bash
git clone https://github.com/Butman76/naidii.git
cd naidii/web && npm install
```

Дальше можно `npm run dev` для локальной разработки. Доступ на сам сервер (SSH) не привязан к
компьютеру — нужны только реквизиты входа на `spb-3-vm-2v0g`, которые есть у пользователя.

Claude Code в этой папке при старте сессии сам подхватывает [`CLAUDE.md`](CLAUDE.md) в корне репозитория,
который указывает читать этот файл и `PIVOT_SERVICE_CARDS.md` — отдельно просить об этом не нужно.
